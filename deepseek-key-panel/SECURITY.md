# 安全政策

这个工具要经手你的 **DeepSeek API Key** 和 **平台登录 Token**，所以安全边界值得写清楚。

## 这个工具怎么处理你的凭据

| 事项 | 说明 |
|---|---|
| 请求发往哪里 | 只有 `api.deepseek.com` 和 `platform.deepseek.com`。**没有任何第三方服务器参与**，不存在"把 Key 送去代查" |
| 本地服务的监听范围 | 只绑定 `127.0.0.1`。局域网、公网都访问不到 |
| 代理白名单 | 只允许转发到上述两个域名（写死在 `server.py` 的 `ALLOWED_HOSTS`），其余一律 403 |
| Cookie | 不转发 Cookie，也不回传 `Set-Cookie` |
| 日志 | 只打印方法、域名、路径、状态码、耗时、体积。**不打印 Authorization 或任何 Key** |
| 落盘 | 服务端不写任何文件。Key 只存在你的浏览器 localStorage（可选，默认关闭） |
| 剪贴板 | 「复制完整 Key」由浏览器完成，不经过服务端 |

## 你需要自己注意的

1. **导出文件是明文的。**「导出纯 Key 列表」和「完整备份」都包含明文 Key，
   等同于 Key 本身。别放网盘、别发人、别提交进仓库。
2. **`.gitignore` 已排除** `keys.txt`、`keys*.txt`、`dskp-*.json` 等敏感文件名 ——
   但如果你把填了真 Key 的文件改成别的名字再提交，它救不了你。
   提交前建议 `git status` 扫一眼。
3. **截图前先打码。** 面板默认对 Key 打码，但余额界面、平台 Token 输入框都在同一页上。
4. **平台 Token 是登录态**，权限等同于你的账号，而且会过期。
   公共电脑上不要勾「记住这个 Token」。
5. **本机安全就是全部安全。** 任何能读你浏览器 localStorage 或能连上
   `127.0.0.1` 的程序，都能拿到这些凭据。

## 已知的设计取舍

- 面板页面与本地代理**同源**，且代理带 `Access-Control-Allow-Origin: *`。
  这意味着你在这台机器上访问的其他网页，理论上可以向 `127.0.0.1:8787` 发请求
  **使用代理转发能力**（但拿不到你浏览器里的 Key，因为 Key 在你自己页面的 localStorage 里，
  且没有任何接口能把 Key 读出来）。
  如果你在意这一点，可以在 `server.py` 里把 `_cors()` 的 `*` 收紧成固定来源。
- 官方用量接口必须用**网页登录 Token**，这是 DeepSeek 的接口设计决定的
  （该接口没有 CORS 头，且不接受 API Key）。本工具没有绕过任何鉴权。

## 报告漏洞

请**不要**开公开 issue。用下面任一渠道：

- GitHub Security Advisories：仓库页 → **Security** → **Report a vulnerability**
- 或直接邮件联系维护者（见 GitHub 主页）

请在报告里包含：复现步骤、影响范围、可能的利用方式。
一般会在 7 天内回复；确认后会在修复版本中致谢（除非你希望匿名）。

## 支持范围

只维护最新发布版本。发现密钥已被泄露时，第一优先级永远是
**去 DeepSeek 控制台吊销 Key**，而不是等修复。
